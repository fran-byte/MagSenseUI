# Technical Resources

## I²C Communication Basics

I²C (Inter-Integrated Circuit) is a serial communication protocol commonly used to connect microcontrollers with peripheral devices such as sensors, displays, EEPROMs and ADCs.

The protocol uses only two signal lines:

- **SDA** (Serial Data): transfers data between devices.
- **SCL** (Serial Clock): synchronizes data transmission.

An I²C network consists of:

- **Master device**: initiates communication and controls the clock.
- **Slave devices**: respond to requests from the master.

### Communication Sequence

A typical I²C transaction follows these steps:

1. The master generates a START condition.
2. The master sends the slave address.
3. The slave acknowledges the request.
4. Data is transmitted or received.
5. The master generates a STOP condition.

### Shared Bus Architecture

Multiple devices can share the same I²C bus provided that each device has a unique address.

In MagSenseUI, the following devices share the same bus:

- SH1106 OLED Display
- MLX90393 Magnetic Sensor

This allows both peripherals to communicate with the ESP32 using only two signal wires.

### I²C Clock (SCL)

Unlike a conventional free-running clock, the I²C clock is generated by the master only when data needs to be transferred.

Key characteristics:

- Controlled by the master device.
- Can stop between transactions.
- Synchronizes the transmission of every bit.
- May operate at different frequencies depending on the application.

For this reason, SCL should be considered a synchronization signal rather than a continuously running clock.
